# خارطة الاعتماد والمواءمة — Goethe B2 + telc B2

**تاريخ البدء:** 2026-11-04  
**قرار المالك:** البدء بمساري Goethe-Zertifikat B2 وtelc Deutsch B2، والمنتج أولاً **منتج تحضير متوافق**.  
**قاعدة الصدق:** لا تُستعمل عبارة «معتمد من Goethe/telc» ولا شعار أي جهة قبل إذن مكتوب منها.

## 1. الفرق بين مرحلتين

### أ) منتج تحضير متوافق

يمكن إثباته داخل المشروع عندما:

1. تحفظ النسخ الرسمية الحالية من أوصاف الامتحان ولوائحه.
2. تتحول كل فقرة رسمية إلى مطلب ذي معرّف ودليل من الكود/المحتوى.
3. يراجع خبير امتحانات مستقل المصفوفة ويوقعها.
4. تبقى النتائج داخل التطبيق تدريبية وتقييماً ذاتياً، لا شهادة.
5. تنجح الاختبارات التقنية والميدانية المحددة أدناه.

### ب) منتج معتمد رسمياً من جهة

لا يمنحه الكود أو CI. لا يتحقق إلا بوثيقة صريحة من الجهة المانحة تحدد حق المنتج في استعمال وصف «معتمد» أو شعارها. قد تكون الجهة لا تعتمد منتجات التحضير أصلاً؛ يجب سؤالها كتابةً قبل أي ادعاء أو نفقة تسويقية.

## 2. ما أُغلق برمجياً في الدفعة الأولى

- أضيف سجل أدلة قابل للقراءة الآلية: `content/accreditation-alignment.json`.
- أضيفت بوابة `npm run audit:accreditation` للتحقق من:
  - وجود الهدفين وروابطهما الرسمية.
  - وجود كل ملفات الأدلة.
  - الفصل بين المحاكاة والنتيجة الرسمية.
  - Goethe: أربع وحدات مستقلة، 60/100 لكل وحدة بلا تعويض، وأزمنة المحاكاة.
  - telc: الكتلة المكتوبة 225 والشفهية 75 وعتبتا 135/45، والأزمنة وSprachbausteine والاستماع مرة واحدة.
  - وجود مادة B2 للقراءة والاستماع والكتابة والتحدث.
- أضيف وضع صارم: `npm run audit:accreditation:strict`. يبقى خروجه غير صفري مقصوداً حتى اكتمال كل التوقيعات الخارجية.
- صُحح تناقض كان يسمح نظرياً بتعويض وحدة Goethe الضعيفة بمجموع 240؛ المخطط الآن يصرح بأن كل وحدة يجب أن تبلغ 60.
- صُحح هدف كتابة Goethe الثاني من 120 إلى نحو 100 كلمة ليتطابق داخلياً مع المحاكاة الحالية؛ يبقى اعتماد الرقم خارجياً معلقاً حتى مراجعة المصدر المحفوظة.
- استُبدلت عبارات «صيغة رسمية موثقة» في واجهة المحاكاة بعبارة مواءمة تدريبية مؤقتة تنتظر مراجعة المصدر.

هذه الخطوات تثبت سلامة الأسلاك والاتساق الداخلي، ولا تثبت وحدها صحة كل تفصيل رسمي في تاريخ اليوم.

## 4. المراحل المتبقية ومعيار إغلاق كل مرحلة

### P1 — تجميد المصادر الرسمية

**المالك:** مسؤول المطابقة.  
**المطلوب:**

- حفظ PDF/HTML الرسمي الحالي لكل جهة وفق ما تسمح به حقوق النشر.
- تسجيل URL وتاريخ الاسترجاع والإصدار وSHA-256.
- استخراج جدول: الأجزاء، الأزمنة، عدد البنود، مرات الاستماع، تعليمات الكتابة/الشفهي، النقاط والنجاح والإعادة.
- مراجع ثانٍ يقارن الاستخراج بالمصدر ويوقعه.

**الإغلاق:** تتحول `sourceReviewStatus` من `official-snapshot-pending` إلى `verified` مع اسم المراجع وتاريخه ومسار اللقطة/المحضر.

### P2 — مراجعة خبير امتحانات

**المالك:** ممتحن أو مدرب مؤهل لكل صيغة.  
**المطلوب:** مقارنة كل عنصر في المحاكاة بالمصدر الرسمي دون نسخ مواد امتحانية محمية.

**الإغلاق:** محضر موقع يحدد لكل مطلب: مطابق، فرق تدريبي معلن، أو عيب واجب الإصلاح. لا يبقى فرق غير معلن.

### P3 — المراجعة اللغوية الكاملة

**المالك:** مراجع ألماني مؤهل + مراجع عربي مستقل.  
**المطلوب:** مراجعة الألمانية والعربية والتعليمات والمفاتيح والنص الصوتي. يبدأ العمل بعينة طبقية، ثم ينتقل إلى جميع المواد المستعملة في نماذج الاعتماد.

**الإغلاق:** سجل مراجعة لكل وحدة، توقيع، وصفر عيب حرج مفتوح. Audio QC الآلي لا يحل محل الاستماع البشري.

### P4 — الدراسة الميدانية والسيكومترية

**المالك:** باحث تقويم تربوي.  
**المطلوب:** بروتوكول أخلاقي، موافقة المشاركين، عينة مناسبة، بيانات مجهلة، تحليل صعوبة وتمييز البنود والثبات، ومقارنة مع نتيجة خارجية حقيقية عند السماح.

**الإغلاق:** تقرير يحدد حجم العينة، الاستبعادات، الثبات، حدود الثقة، البنود المحذوفة، وعدم التحيز المعروف. لا يكفي عدد نجاحات داخل التطبيق.

### P5 — الأجهزة والإتاحة والخصوصية والقانون

**المالكون:** QA بشري، خبير إتاحة، ومستشار قانوني.  
**المطلوب:** Android/iOS/Desktop، لوحة مفاتيح وقارئات شاشة، PWA update/offline/storage pressure، ميكروفون، سياسة الخصوصية، حقوق المواد، واستعمال العلامتين.

**الإغلاق:** مصفوفة أجهزة موقعة، تقرير WCAG بشري، ورأي قانوني مكتوب. اختبارات Chromium الحالية دليل تقني فقط.

### P6 — طلب الختم أو الاعتماد إن كان متاحاً

**المالك:** مالك المنتج.  
**المطلوب:** سؤال Goethe-Institut وtelc gGmbH كتابةً عن وجود برنامج اعتماد لمنتجات التحضير وشروط استعمال الاسم أو الشعار.

**الإغلاق:** أحد أمرين فقط:

1. وثيقة اعتماد/ترخيص صريحة، وعندها يحدّث الادعاء بالنص المسموح حرفياً؛ أو
2. إثبات أن المنتج متوافق ومستقل، مع استمرار منع عبارة «معتمد رسمياً».

## 5. موضع GGP وCEFR

بُنيت مصفوفة داخلية حتمية من المنهج الحالي في `content/grammar-profile-matrix.json`: ‏87 موضوعاً و313 سمة مرشحة مشتقة من عبارات القواعد، مع أدلة على مستوى الموضوع وحالة مراجعة مستقلة لكل بعد. لم يُحتفظ بادعاء «150 سمة» لأنه لا يوجد في المستودع مصدر مرخص يثبت هذا العدد أو خريطته. المصفوفة ليست بديلاً عن مطابقة صيغة Goethe/telc ولا شرط اعتماد تلقائياً؛ تبقى `internal-evidence-map-not-official-ggp` حتى حفظ المصدر والترخيص وربط السمات وتوقيعها. التفاصيل في `docs/GGP_GRAMMAR_PROFILE.md`.

## 6. أوامر الحكم

```bash
# يجب أن ينجح في CI: يثبت التنفيذ والاتساق الداخلي ويعرض المعلقات الخارجية
npm run audit:accreditation

# يجب أن يفشل حالياً بخروج 2: لا ينجح إلا بعد توقيع كل المصادر والمراجعات الخارجية
npm run audit:accreditation:strict
```

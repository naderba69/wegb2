# بروتوكول الاختبارات الواقعية والأدلة الخارجية

**الخطة الآلية:** `content/real-world-validation.json`
**سجل الأدلة الخارجية:** `content/external-evidence.json`
**خارطة المواءمة:** `content/accreditation-alignment.json`

## 1. قاعدة الفصل

هناك ثلاث طبقات لا يجوز دمجها لفظياً:

1. **اختبار آلي مخبري:** Chromium وLighthouse وAudio QC وCI.
2. **اختبار واقعي:** جهاز/متصفح/قارئ شاشة/ميكروفون أو مستخدم حقيقي، مع بيئة وتاريخ وأثر.
3. **مراجعة خارجية:** شخص مؤهل مستقل يراجع المصدر أو اللغة أو الامتحان أو القانون ويوقع المحضر.

نجاح الطبقة الأولى لا يغلق الثانية أو الثالثة.

## 2. المصفوفة الواقعية

الخطة الحالية تحتوي 23 حالة موزعة على:

- هواتف ولوحيات Android وiOS.
- Chrome وEdge وFirefox وSafari على أنظمة فعلية.
- لوحة المفاتيح وNVDA وVoiceOver وTalkBack والتكبير والتباين.
- تثبيت PWA وتحديثها وضغط التخزين وانقطاع الشبكة.
- تشغيل الصوت والميكروفون والسماعات ورفض الإذن والضجيج.
- اختبار قابلية الاستخدام ودراسة التعلم وتحليل البنود.

كل حالة تبدأ `planned`. لا تصبح `passed` أو `failed` أو `blocked` إلا إذا احتوت:

- اسم المنفذ.
- تاريخ التنفيذ.
- وصف الجهاز وإصدارات النظام والمتصفح.
- كل خطوات ومعايير القبول.
- لقطات أو سجل أو فيديو أو ملف نتائج.
- توقيع المحضر أو بصمته.

## 3. الدراسة الميدانية

لا يُختار حجم العينة لإغلاق رقم تسويقي. قبل الجمع يجب تحديد:

1. سؤال البحث والفرضية الأساسية والثانوية.
2. مقياس النتيجة وأداة مستقلة قدر الإمكان.
3. الحد الأدنى المهم تربوياً.
4. تحليل قوة إحصائية وحجم عينة مع تعويض الانسحاب.
5. معايير الإدخال والاستبعاد قبل رؤية النتائج.
6. موافقة واضحة وحق الانسحاب وتقليل البيانات وإخفاء الهوية.
7. خطة المفقودات والتعدد وفواصل الثقة وحجم الأثر.
8. قواعد صعوبة وتمييز البنود والثبات وDIF عندما تكفي العينة.

لا تُنسخ بيانات شخصية أو أصوات المشاركين إلى Git. يحفظ المستودع بروتوكولاً وبيانات مجهلة أو ملخصات وبصمات فقط.

## 4. ملف 2 + 10 + 7

سجل `external-evidence.json` يمثل بالضبط:

- مصدرين رسميين: Goethe B2 وtelc B2.
- عشر مراجعات متطلبات مرتبطة بهما.
- سبعة حواجز خارجية: المصدر، اللغة، خبير الامتحان، الدراسة، الأجهزة، القانون، والجهة المانحة.

وجود المواد على الإنترنت يسمح **بجمع المصدر**، لكنه لا ينشئ تلقائياً:

- مراجعاً مستقلاً.
- مؤهلاً مهنياً.
- توقيعاً.
- اختبار هاتف أو ميكروفون.
- رأياً قانونياً.
- رداً من Goethe أو telc.

## 5. حفظ المصدر

عند توفر بيئة شبكة مسموح لها بالنطاق الرسمي:

1. نزّل HTML/PDF وفق شروط الموقع وحقوق النشر.
2. لا تعدّل الملف الخام.
3. احسب `sha256sum`.
4. سجل URL، تاريخ UTC، نوع الملف، عنوانه وإصداره.
5. إن كان نشر الملف في Git غير مسموح، خزنه في مخزن أدلة مقيد وسجل البصمة والمسار المرجعي فقط.
6. يراجع شخص ثانٍ الاستخراج بنداً بنداً ويوقع نموذج المراجعة.

## 6. أوامر الحكم

```bash
npm run evidence:hash -- evidence/path/to/artifact.pdf
npm run audit:evidence
npm run audit:evidence:strict   # exit 2 حتى توقيع 19/19
npm run audit:real-world
npm run audit:real-world:strict # exit 2 حتى توثيق كل الجلسات
```

البوابات العادية تفحص المخطط والصدق وعدم تزوير النتائج. الصارمة هي بوابة جاهزية الإطلاق المدعوم بأدلة خارجية.
